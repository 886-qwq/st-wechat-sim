# 微信模拟器开发路线

## 阶段 1：可安装的文字微信 MVP

- 第三方 SillyTavern 扩展结构
- 扩展菜单入口和全屏微信界面
- 当前角色、当前模型和近期上下文
- 按角色保存的独立微信记录
- 纯对话约束、字数限制和消息气泡拆分
- 外部记忆适配器

验收条件：在目标酒馆版本中启用插件，点击“微信模拟器”，能够连续聊天；刷新后记录仍存在；回复没有明显旁白或 Markdown。

## 阶段 2：语音输入与角色语音

语音通话不是单一 TTS API 就能完成。完整链路需要一个低延迟服务：

```text
手机麦克风
  -> 实时语音识别 ASR
  -> 语气/情绪分析
  -> 当前角色模型回复
  -> 带情绪标签的 TTS
  -> 音频流回到手机
```

需要实现：

- 麦克风权限、录音、VAD 和打断
- 至少一个 ASR 服务
- MiniMax / ElevenLabs 的 TTS 适配器
- 角色到音色 ID 的映射
- 情绪标签规范和标签清洗
- API Key 的服务端代理，避免暴露在浏览器
- Termux 上的反向代理与跨域配置

MiniMax 和 ElevenLabs 负责文字转语音，不负责识别用户说话。识别和语气判断需要另接 ASR 或多模态模型。

## 阶段 3：角色图片消息

- 生图服务适配器
- 角色图片提示词构建
- 图片风格、尺寸、模型、负向提示词等参数页
- 微信式图片气泡和查看器
- 从用户自然语言触发图片意图，或由文字模型输出受控的结构化调用
- 图片保存与聊天记录持久化

“训练风格”与普通生图参数字段不是同一能力。若采用 NovelAI、MiniMax 或第三方图片 API，需要分别确认其风格参考、微调或训练能力。

## 阶段 4：柏宝书双向记忆

需要获取实际安装的柏宝书源码和版本，确认：

- 记忆存储位置与数据结构
- 是否支持外部 API、事件或函数调用
- 是否按角色/聊天隔离
- 主聊天消息如何触发记忆提取
- 是否可以写入“不显示在主聊天”的记忆事件

不能把微信记录直接塞进主聊天，否则会污染小说式剧情。合理方案是构建显式双向适配器：

```text
柏宝书记忆 -> WeChat recall() -> 生成提示词
微信一轮对话 -> WeChat remember() -> 柏宝书持久化
```

## 当前尚缺的项目输入

1. 目标 SillyTavern 版本或安装目录
2. 柏宝书插件目录或 GitHub 地址
3. 选定语音服务及其 API 文档
4. 选定生图服务及其 API 文档
5. GitHub 仓库地址和登录方式

其中 1、2 是继续联调的必要条件；3、4 可以并行设计，但不应在协议未确认时写死。
