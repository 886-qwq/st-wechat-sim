# ST-iPhonie 参考结论

参考项目：<https://github.com/hey8v0/ST-iPhonie>

本项目只借鉴公开的接口与产品结构，没有复制其源码或大型素材。参考仓库当前没有检测到许可证字段，因此后续即使需要复用具体代码，也应先取得作者授权。

## 值得采用的设计

### 1. 通过酒馆全局上下文接入

参考项目使用：

```js
globalThis.SillyTavern.getContext()
```

从上下文读取角色、聊天、事件、扩展设置和当前模型接口。这比直接依赖内部文件的相对导入更耐版本变化。

`0.2.0` 已改用这一方式，并保留旧版 `generateQuietPrompt` 回退。

### 2. 电话与正文分开生成

参考项目不会把手机聊天直接追加到酒馆主聊天，而是用当前连接的文字模型生成一段独立回复。请求中显式放入：

- 当前角色卡或联系人设定
- 用户人设
- 最近正文
- 手机聊天记录
- 世界书、长期记忆和知情范围
- 聊天预设的输出规则

`0.2.0` 已加入角色卡、角色字段别名、用户人设和近期主聊天；完整世界书接口仍待酒馆版本联调。

### 3. 手机 UI 与酒馆页面隔离

参考项目把手机界面放在独立 iframe 中，通过 `postMessage` 与酒馆侧连接。这样可以减少 CSS、快捷键和第三方扩展之间的冲突。

当前项目仍直接在酒馆页面中渲染全屏界面。后续如果出现样式冲突，应迁移到 iframe，而不是继续提高 CSS 优先级。

### 4. 对话与正文双向交接

参考项目可以：

- 从正文提取最近消息作为手机聊天背景
- 选择手机消息，注入下一次正文生成
- 通话结束后把记录留在手机私聊

这比把手机消息直接写进主聊天更适合你的需求。柏宝书桥接也应遵守“独立存储、显式读取、显式写入”的原则。

## 需要特别澄清的功能

参考项目的“打电话”是：

```text
角色回复文字 -> 角色的 TTS 声音朗读
用户 -> 打字回复
```

它并没有把用户的麦克风录音送去做实时语音识别。README 中明确写的是“你打字回话”。

如果你的目标是接近豆包打电话：

```text
麦克风 -> VAD -> 流式 ASR -> 情绪/语气理解
-> 角色模型 -> 流式 TTS -> 播放与打断
```

这需要额外的 ASR、低延迟后端和音频传输，不能仅靠 MiniMax 或 ElevenLabs
的 TTS 接口完成。

## 生图设计

参考项目支持 NovelAI、GPT 生图和 ComfyUI，并把出图提示词与角色参考图纳入生成请求。生图结果作为手机图片消息显示。

后续应优先复用酒馆已配置的生图服务，或实现独立适配器；API Key 不应提交到 GitHub。

## 下一步优先级

1. 在你的实际 SillyTavern 版本中测试 `0.2.0` 的微信文字聊天
2. 获取柏宝书源码，完成真实记忆适配
3. 若要接近参考项目，迁移 iframe 界面并增加“手机消息带入正文”
4. 接入 TTS，先实现角色语音回复
5. 再实现麦克风录音、ASR 和实时通话
6. 最后接入生图与角色图片消息
